# #180 「정보가 없다」에 기대는 ELIGIBLE 막기 — 설계

**Notion:** #180 (`40d41e61-65c0-8103-8ba2-eaff116bb7f1`) · **앞 티켓:** #80 PR #14 유보, #82 프로필 불가 규칙

## jw 기준

'정보가 없음' 프로필 칸에 정답 라벨 'ELIGIBLE'이 붙는 케이스가 발생하지 않는다

(되물은 뒤: 「정답 라벨」은 시스템 판정, LLM이 낸 ELIGIBLE을 뜻한다)

## 1. 지금 상태

- ELIGIBLE을 낼 수 있는 축은 무주택(`homeless`)·세대주(`householder`) 둘뿐이다. 나머지 축은 ELIGIBLE guard(`verdict.py` `REQUIRED_FIELDS`)가 NEED_INFO로 바꾼다
  - 라벨 규칙도 같다(`docs/75-label-rules.md` 13줄). ELIGIBLE 줄은 `homeless-2`(`homeless_now`=true)와 `householder-2`(`is_household_head`=true) 둘이다
- 무주택·세대주 축의 ELIGIBLE은 지금 LLM이 정한다. guard는 칸이 비었는지만 보고, 이유 문장은 LLM이 쓴 그대로 화면에 나간다
- **#80 PR #14 유보 사례** — 더샵 분당하이스트 × 꽉 찬 프로필 × 무주택 축. 이유: 「… 제53조상 예외 사유에 해당한다는 정보가 없어 … 무주택세대구성원으로 볼 수 있습니다」
  - 제53조 예외 사유는 프로필에 칸이 없는 정보다. LLM이 「없으니 해당 안 함」으로 읽고 이유에 썼다
  - 판정값 자체는 라벨 규칙 `homeless-2`와 같다(`homeless_now`=true). 틀린 것은 화면에 나간 이유다

## 2. 무엇을 만드나 — 프로필 가능 규칙

#82 프로필 불가 규칙의 짝이다. 라벨 규칙의 ELIGIBLE 줄 둘을 코드로 옮긴다.

| 규칙 | 축 | 조건 | 이유 문장 |
| --- | --- | --- | --- |
| `homeless-2` | 무주택 | `homeless_now` = true | 프로필에서 지금 무주택(`homeless_now`=true)이라 무주택세대구성원 요건을 채운다(제53조) |
| `householder-2` | 세대주 | `is_household_head` = true | 프로필에서 세대주(`is_household_head`=true)라 세대주 요건을 채운다(제2조제3호) |

- 적용 자리: `judge_one`에서 프로필 불가 규칙 다음. LLM 호출이 성공했고, 인용 guard가 판정을 UNVERIFIABLE로 바꾸지 않았을 때만 건다
  - 인용이 모두 기각된 판정(`forced`)에는 걸지 않는다. 근거 없는 ELIGIBLE이 화면에 나가지 않게 하려는 것이다. 불가 규칙은 `forced`여도 건다(#82) — 틀린 ELIGIBLE이 더 위험한 쪽이라 둘을 다르게 둔다
- 걸리면 모델 판정이 무엇이든 ELIGIBLE로 바꾼다. `ruled=True`, `rule`에 규칙 번호, `original_verdict`에 모델 판정, `reason`은 위 이유 문장으로 바꾼다(#82 불가 규칙과 같은 처리)
- 불가 규칙과 가능 규칙은 같은 칸의 true·false라 동시에 걸리지 않는다. 그래도 순서는 불가 규칙이 먼저다
- ELIGIBLE guard는 그대로 둔다. 칸이 비면 LLM ELIGIBLE을 계속 NEED_INFO로 바꾼다
- 응답 체크리스트 `note`: 「프로필 가능 규칙 homeless-2가 ELIGIBLE로 정함 (모델 판정 NEED_INFO)」 꼴. 불가 규칙 문구는 그대로다

결과적으로 무주택·세대주 축은 LLM 호출이 성공하면 판정값과 이유를 코드가 정한다. LLM은 인용 근거를 대는 데 쓰인다.

## 4. 숫자 읽는 법

- **jw 기준 측정값은 이번 변경 전에도 0이다.** 프로필 칸이 빈 ELIGIBLE은 #80 ELIGIBLE guard가 이미 막고 있다. 이번 티켓이 바꾸는 것은 화면에 나가는 이유(같이 재는 것 첫 줄)와, 칸이 찼는데 LLM이 놓친 ELIGIBLE이다
- **규칙과 정답 라벨이 같은 문서에서 나왔다.** 프로필 가능 규칙은 라벨 규칙 ELIGIBLE 줄을 옮긴 것이다. 판정 정확도가 오르면 거의 정의상 오른 것이다(#82와 같다)
- **「정보가 없음」 칸 정의가 결손 분석에 기댄다.** 결손 분석 표가 축에 필요한 정보를 빠뜨렸으면 측정값도 같이 0으로 나온다. #82에서 결손 분석은 정답 라벨 `need`와 378/378 같았다
