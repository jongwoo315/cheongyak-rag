## 2. 설계 결정

- **링크는 상세 HTML에서 찾는다.** odcloud API에는 첨부 URL이 없다. `atchmnflSeqNo`·`atchmnflSn`은 HTML에만 있다
- **확장자는 `Content-Disposition`의 파일 이름에서 읽고, 파일 앞 바이트로 한 번 더 본다.** `Content-Type`은 늘
  `octet-stream`이다. 앞 바이트: PDF `%PDF-` · HWP(OLE) `D0 CF 11 E0` · HWPX(zip) `PK\x03\x04`. 둘이 다르면 앞 바이트를 따르고
  어긋난 사실을 목록에 적는다
- **PDF가 「오류 없이」 받아졌다 = HTTP 200 + 앞 바이트가 `%PDF-` + `pymupdf`로 열리고 쪽수 1 이상.** 셋 중 하나라도 아니면 오류다
- **격리 = 저장 위치를 나누고 목록에 남긴다.** PDF는 `data/raw/notices/`, 그 밖은 `data/raw/notices/quarantine/`.
  격리한 파일은 읽지 않는다
- **결과는 공고마다 하나로 정한다** — 아래 「공고문 수집 결과 5개」. 링크가 둘 이상이면 링크마다 줄을 남기고, 공고 결과는
  가장 나쁜 것(error > other > hwp > pdf)으로 정한다
- **재실행은 파일이 있고 크기·sha256이 목록과 같으면 받지 않는다.** 상세 페이지는 다시 받는다(링크가 바뀌었는지 보려고)
- **요청 사이 0.5초, 429·5xx·연결 오류는 1·2·4·8초 뒤 최대 4번 다시.** #71 `notice.py`의 재시도 방식을 따른다.
  첨부 하나가 50MB를 넘으면 받다 멈추고 오류로 센다
- 서비스 키가 필요 없다(청약홈 정적 페이지). `.env`는 DB 주소만 읽는다

## 3. 공고문 수집 결과 5개 (개념 표에 넣을 것)

| 값 | 뜻 |
| --- | --- |
| `pdf` | 공고문을 받았고 PDF로 열린다 |
| `hwp` | 받은 파일이 HWP·HWPX라 격리했다 |
| `other` | 받은 파일이 PDF·HWP가 아니라 격리했다 |
| `no_link` | 상세 페이지에 공고문 링크가 없다(지금은 LH 10건) |
| `error` | 받기가 실패했거나(HTTP·시간 초과·크기 초과), PDF라는데 안 열린다 |

## 4. 지표

| 값 | 정의 |
| --- | --- |
| 오류 수 | 공고문 링크가 있는 공고 중 결과가 `error`인 공고 수 |
| PDF 수 | 결과가 `pdf`인 공고 수 |
| 격리 수 | 결과가 `hwp`·`other`인 공고 수(각각) |
| 링크 없음 | 결과가 `no_link`인 공고 수와 번호 |
| 재실행 새 다운로드 | 같은 명령 두 번째 실행에서 새로 받은 파일 수 |
| 텍스트 없는 PDF | 열리지만 모든 쪽에서 뽑힌 글자가 0인 PDF 수(스캔본 의심). 오류로 세지 않는다 |
