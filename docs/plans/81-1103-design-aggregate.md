## B8 집계 규칙

바탕 설계 §168의 우선순위를 쓴다: `INELIGIBLE` > `UNVERIFIABLE` > `NEED_INFO` > `CONDITIONAL` > `ELIGIBLE`. 여럿을 합치면 가장 앞의 값이 결과다.

바탕 설계가 정하지 않은 것 셋을 여기서 정한다.

| 항목 | 고른 것 | 안 고른 것과 이유 |
| --- | --- | --- |
| 특별공급 유형 질의 여러 개 | **유형마다 따로 합친다.** 일반공급 판정 = 일반 축(무주택 · 청약통장 · 거주 · 재당첨 · 세대주 중 켜진 것). 특별공급 유형 X 판정 = 일반 축 + 소득·자산 축 + 유형 X 질의 | 전부 한 번에 합치기. 더샵 분당하이스트 × 꽉 찬 프로필은 다자녀·신혼부부 `INELIGIBLE` 때문에 공고 전체가 `INELIGIBLE`이 된다. 특별공급은 여러 유형 중 하나를 골라 신청하는 경로라 한 유형이 안 된다고 공고 전체가 안 되는 게 아니다 |
| 전역 판정 | **일반공급 판정**을 전역 판정으로 쓴다. 특별공급 유형별 판정은 그 아래 따로 싣고, `ELIGIBLE`·`CONDITIONAL`인 경로를 「신청 가능한 경로」로 모은다 | 경로 중 가장 좋은 값. 경로가 다른 판정을 한 값으로 접으면 어느 경로 얘기인지 응답에서 사라진다 |
| 판정이 없는 하위 질의(호출 실패, `verdict=None`) | `UNVERIFIABLE`로 센다 | 빼고 합치기. 빠진 축이 결과를 좋게 만든다(예: 실패한 축이 실제로는 `INELIGIBLE`) |

- 꺼진 축은 합치지 않는다. 켜진 축이 하나도 없는 경로는 판정을 `None`으로 둔다
- 세대주 축이 특별공급 유형 일부(노부모 부양)에만 걸린다는 차이는 이번에 반영하지 않는다. ceiling을 코드 주석에 남긴다

## B9 응답

공고 하나 × 프로필 하나 → 응답 하나(JSON으로 쓸 수 있는 dataclass + 사람이 읽는 텍스트 렌더). LLM을 부르지 않는다.

- 전역 판정(일반공급) · 특별공급 유형별 판정 · 신청 가능한 경로
- 축별 체크리스트: 축 이름 · 판정값 · 이유 · 조건 · 필요한 정보 · 인용
- 인용마다 근거 원문과 출처. 원문은 `chunks` 행의 `text`를 그대로 싣는다(조문은 공고 MST 행, FAQ는 `faq` 행)
  - 출처: 조문은 「주택공급에 관한 규칙 제N조」와 법령 버전(MST·시행일), FAQ는 「2024 주택청약 FAQ Qn」. 링크는 실제로 열리는 것만 싣는다(구현이 HTTP 200을 한 번 확인한 형식만)
- 가점: #77 `score`의 범위(부분 프로필이면 최소~최대)
- `questions`: 빈 목록(#82)
- **검색 밖 언급 표시**: 이유 문장에 나온 조 번호(`제N조`, `제N조의M`)와 FAQ 번호(`Qn`) 중 그 하위 질의 검색 결과(`context_labels`)에 없는 것을 하위 질의마다 붙인다

## 측정 — jw 기준을 어떻게 재나

표본은 #80과 같다(공고 6건 × 프로필 3종, 하위 질의 135개). system 프롬프트를 바꾸지 않아 캐시를 그대로 읽는다(LLM 호출 0회가 기대값).

### 1. B8이 규칙대로 합치는가

- 규칙 일치(테스트): 일반 축 5개 + 소득·자산 + 특별공급 유형 질의 1개, 7칸마다 「꺼짐」과 판정값 5개(6가지)를 넣는 조합 6⁷ = 279,936개 전부. 테스트 안의 기대값은 우선순위 목록의 순번 최솟값으로 따로 계산한다 <!-- style-exempt -->
- 실데이터 대조(측정): 18쌍의 실제 최종 판정으로 응답을 만들고, 측정 코드가 B8 코드를 부르지 않고 같은 규칙을 다시 계산해 경로별 판정이 다른 것을 센다
- 측정이 구현과 같은 규칙을 옮겨 쓰므로 둘이 같이 틀릴 수 있다. 그래서 규칙 일치 테스트의 기대값은 우선순위 목록 하나에서만 나오게 한다

### 2. 검색에 없는 답이 나오는지 확인할 수 있는가

- 응답의 검색 밖 언급 표시와, 측정 코드가 이유 원문·`context_labels`에서 따로 센 값이 다른 하위 질의 수
- 응답에 실린 근거 원문 중 그 하위 질의 검색 결과에 없거나 `chunks` 원문과 글자가 다른 것의 수
- 착수 때 실측(PR #14 `runs/80/last_run.json`, main 세션이 셈): 이유 문장의 조 번호 언급 145개 중 그 하위 질의 검색 결과에 없는 것 65개, 하위 질의 135개 중 그런 언급이 있는 것 15개, 최종 `ELIGIBLE` 8개 중 0개. FAQ 번호는 세지 않았다
- 조 번호 언급이 검색 밖이라는 것은 「LLM이 검색에 없는 조를 이유에 끌어왔다」는 사실까지다. 그 조가 실제로 맞는 근거인지는 이 측정이 말하지 않는다
