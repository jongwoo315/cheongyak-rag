### 읽는 법

- guard 전은 인용 대조까지 마친 LLM 판정(캐시 응답 그대로)이고 guard 후는 최종 판정이다. guard는 축 단위 규칙이라 jw 기준 0은 규칙이 빠짐없이 걸렸다는 확인이다. LLM이 지어내지 않게 됐다는 뜻이 아니고, 지어낸 값은 guard 전 수로 본다
- 꺼진 축 호출은 `notices`·`notice_models`를 SQL로 직접 읽어 따로 계산한 켜짐 목록(#79 `independent_on`)에 없는 축의 판정 수다. `axes.plan`과 같은 설계를 옮겨 적었으므로 같이 틀릴 수 있다
- DB에 없는 라벨은 측정 코드가 `verdict.py`의 대조 함수를 부르지 않고 `chunks`를 SQL로 다시 센 값이다. 조문은 공고의 법령 버전(MST) 행만 본다
- 인용이 판정 내용을 실제로 뒷받침하는지는 자동으로 재지 않는다. 4절 표본을 사람이 읽는다
- `strict` schema가 5값 밖 응답을 막으므로 파싱에 실패한 응답은 「판정 없음」에 센다
- 판정이 맞았는지는 정답이 없어 이번에 안 잰다(골든셋 #75)
- PR #12 값은 `runs/80/pr12_baseline.json`이고 출처는 1c06665:runs/80/last_run.json (PR #12, 닫음). 같은 표본·같은 프롬프트라 guard 전 값은 이것과 같아야 한다
- 처리 시간은 값만 적는다(baseline 없음): 호출 0 (재시도 0) · 캐시 135 · 입력 0 · 출력 0 토큰 · $0.0000 · 공고×프로필 하나 중앙값 0.1초 · 최댓값 2.4초
